# ADR-003：使用静态 HTML 与对话反馈

状态：Proposed

## 决策

MVP 不迁移旧 Review Server。系统生成可离线打开的静态 HTML，用户通过 Codex 对话选择路线、提交修改意见和确认版本。

## 原因

- 非 coder 更容易打开 HTML，而不是启动和理解本地服务。
- Codex 对话已是主要入口，可以承载自然语言反馈。
- 静态文件更容易归档、分享和重建。

## 结果

- HTML 页面中的按钮不承担关键状态写入。
- 每条反馈必须由运行引擎保存，并关联目标版本。
- 如果后续证实大量用户需要页面内批注，再将交互式 Review 作为独立增强，而不是 MVP 前提。
