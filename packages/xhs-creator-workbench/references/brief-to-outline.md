# Brief 到内容大纲

## 旧工具中保留的控制逻辑

保留 `readNote-scripts-agent` 的内容控制原则和品牌方熟悉的 7 段分镜交付格式，但不要复用其单一博主与四个固定品类：

1. 先按 `品牌 + 产品 + 场景 + 节点 + 主题` 判断内容语境，单点关键词不能决定路线。
2. 生成前检查品类、品牌、产品、场景、节点、主题、受众痛点和硬约束八类信息。
3. 缺口只有在会改变路线、造成合规风险或影响对外交付时才阻断；其余缺口作为显式假设。

## Brief Intake

保存原始文件及摘要，提取结构化 Brief，并将内容分为：

- 原文明确事实
- 系统推断及置信度
- 仍需用户确认的问题

缺少品牌、产品、交付物或关键合规约束时先确认。非关键缺口允许带显式假设继续。

原件必须按 SHA-256 保存在项目私有目录。提取内容要保留页码、段落或单元格 Locator；PDF/DOCX/XLSX 的图片、批注、公式结果和版式不能仅凭文本提取假装已验证。

## 路线

读取项目绑定的 Baseline 快照和已确认 Creator Playbook。Baseline 提供事实、证据和目标边界；Playbook 提供当前主轴、路线模板、语言和商业护栏。若 Baseline 含 `human_context`，同时读取团队确认的目标定位和目标受众：它们决定内容希望走向哪里，Evidence Claims 约束表达怎样仍然像本人。不得把目标受众误写成已经由评论或数据证明的现有粉丝。

历史回测必须记录并排除对应已发布笔记的 Evidence。Task 只能读取过滤后的 Creator Context；被排除笔记、最终脚本、最终发布正文和镜头顺序不得用于生成路线或大纲。回测只验证当前系统能否独立形成合理方案，不以复刻最终稿为目标。

若 `human_context` 含 `commercial_guardrail`，将其作为路线与大纲约束。标记为“少见例外”的结构不得成为默认推荐，只能在 Brief 明确强制时启用，并在风险中说明原因。

默认只生成一条最推荐、可直接推进的路线，因为品牌 Brief 通常已经明确主题与活动。只有用户明确要求多个方向或指定数量时，才生成 2–3 条。

生成多条时，路线之间至少在核心矛盾、场景、产品角色或情绪路径中的两项不同。不要为了凑数量制造只有标题或措辞差异的伪路线。

每条路线包含：内容命题、核心张力、场景、情绪路径、产品进入方式、博主适配证据、Brief 覆盖和风险。

推荐一条路线，但在生成详细大纲前等待用户选择。

## 大纲

为选定路线创建不可覆盖的 Outline 版本。大纲使用“双层结构”：上层回答为什么这样讲，下层回答具体怎么拍。每版包含：

- 选题名、暂定标题和 Hook
- 精确目标总时长和总预计时长范围
- 7 段叙事分组：段落、秒数范围、叙事目标、镜头摘要、大致口播、花字和品牌露出
- 逐镜头 Shot Rows：镜号、所属分组、精确秒数、拍摄场景 / 画面内容、景别 / 机位、大致口播 / VO、花字、音效 / 拍摄要点和品牌露出
- Brief 覆盖矩阵
- 博主适配依据
- 假设、风险和待确认项

默认沿用旧 scripts-agent 的 7 段节奏，方便助理直接复制进品牌模板：

| 段落 | 默认秒数 | 叙事职责 |
| --- | --- | --- |
| 1. 开场 Hook | 6–8 秒 | 用问题、反差或当下状态让用户停留 |
| 2. 痛点铺垫 | 10–12 秒 | 建立真实场景和用户困扰 |
| 3. 转折 / 决策 | 8–10 秒 | 说明为什么开始尝试或改变 |
| 4. 产品自然进入 | 10–12 秒 | 让产品作为行动的一部分出现 |
| 5. 行动 / 体验验证 | 15–18 秒 | 用动作、细节和体验承接卖点 |
| 6. 结果 / 感受回收 | 8–10 秒 | 回到博主本人感受，不做绝对化承诺 |
| 7. 收尾互动 | 6–8 秒 | 收束主题并给出自然互动点 |

这是默认策略骨架，不是把 7 段直接当作 7 个镜头。Brief 明确规定视频时长、段落、平台形式或品牌模板时，以 Brief 为准；没有覆盖要求时默认保留 7 段。

每一段必须拆成一个或多个 Shot Rows。镜号从 1 连续编号，每行只描述一个可拍摄、可计时的镜头单元；一行至少包含画面动作、景别 / 机位和大致口播。对 120 秒以上视频，应按实际叙事需要细拆，避免一行塞入多个场地、动作或口播任务。

时长实行三层一致性校验：

1. 每个 Shot Row 使用精确秒数，便于助理直接复制进品牌模板。
2. 同一分组下所有 Shot Rows 的秒数之和，必须落在该段的秒数范围内。
3. 所有 Shot Rows 的秒数之和必须等于 `target_duration_seconds`，并落在总预计时长范围内；总预计时长范围仍必须等于各段范围之和。

产品不应只在分组摘要中出现。凡涉及产品出镜、产品特写、口播卖点或 SKU 组合展示，必须落到具体 Shot Row 的 `brand_presence`；花字、音效和拍摄动作分别写入对应字段，避免混在口播里。

“大致口播”用于让品牌方理解每个镜头大概会表达什么，不是逐字定稿，也不替博主本人写最终口播脚本。句子应接近可读表达、足够支持审核，同时为博主创作保留空间。

暂定标题只用于帮助理解路线。正式发布标题在大纲过审后作为 Publication Copy 生成。

AI 只写 candidate。必须由 `brief finalize`、`routes finalize` 或 `outline finalize` 校验后才能成为业务对象。任何大纲修订都创建新版本，不覆盖前一版；原始内部反馈单独保存。
