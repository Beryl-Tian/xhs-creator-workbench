# Creator Playbook 生成协议

Creator Baseline 是事实、证据和团队目标的底座；Creator Playbook 是它的可执行投影。Playbook 用于选题、内容路线、大纲和发布文案，不替博主写最终逐字口播稿。

## 输入优先级

1. 已确认 Baseline 的 `human_context` 是团队明确目标与商业边界。
2. Baseline claims 是可复用判断，必须保留其事实状态和适用范围。
3. 最新 30 篇窗口定义“当前主轴”；更早窗口只用于识别历史能力。
4. Evidence 用于提供真实标题、句式和内容例子，不得把不存在的例子写成博主原话。

## 输出要求

- 提炼 2–5 个当前内容主轴，每项说明角色和适用场景。
- 历史能力单列，写明当前只作为次级能力或特定品牌场景调用。
- 给出 3–5 条路线模板。结构需要能直接翻译成“秒数 / 镜头 / 大致口播”的大纲，但不写最终逐字稿。
- 给出 3–5 个标题公式和 2–5 个正文结构；真实例子必须带 `evidence_id`。
- 语言工具箱区分保留、避免、CTA 和真实句式。
- 商业合作先写默认自然植入路径，再写品牌强约束下的例外路径。例外不得反过来成为博主默认风格。
- 区分样本观察到的受众和团队希望吸引的目标受众，并把后者翻译为可检查的内容信号。
- 结尾给助理一份 5–12 项出稿检查清单，并记录数据边界。

## 可追溯规则

- `claim_ids` 必须存在于绑定 Baseline。
- `evidence_id` 必须存在于绑定 Baseline 的主样本或纵向样本。
- 视觉、镜头语言或受众人口属性若没有证据，只能留在限制项，不能补写成确定结论。
- 任何新策略假设若不能从已确认目标或 claim 推导，不进入正式 Playbook。

## 人工闸门

Finalize 只生成 `pending_confirmation` 版本和本地 HTML。助理或博主确认后才可用于新项目；修改应创建新版本，不覆盖历史版本。
